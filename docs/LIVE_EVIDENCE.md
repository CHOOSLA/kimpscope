# 김프 계산 기준과 실시간 근거 (2026-10-23)

## 관찰

- 운영 `/api/market` 응답의 김프가 10개 코인 모두 ±0.8% 이내였다(BTC −0.01%). 환율로 업비트 USDT/KRW 체결가를 썼기 때문이다. 테더 가격에는 이미 국내 프리미엄이 붙어 있어, 이를 환율로 쓰면 김프가 상쇄된다. 같은 시각 공개 기준환율은 1,325.13원, USDT/KRW는 1,335원이었다(테더 프리미엄 약 +0.7%).
- 같은 응답이 14:01 이후 15분째 `stale: true`였지만 원인은 응답에도 로그에도 남지 않았다. 캐시가 있으면 오류를 숨기고 이전 값을 돌려주는 구조였다.
- 빗썸 대체 경로는 USDT 시세가 없을 때 환율 1,380원을 고정값으로 썼다.
- "지금 가격", "입금 되나" 같은 질문은 근거와 무관하게 정규식으로 모두 거절했다. 문서 속 API 예시 가격을 현재가로 답한 오류(2026-10-22) 때문에 넣은 규칙이다. 반면 "지금 김프"는 정규식에 걸리지 않아 문서 속 숫자로 답할 수 있었다.

## 조치

**환율** (`backend/fx.py`): 김프는 원/달러 기준 환율로 계산한다.
1. `KOREAEXIM_API_KEY`가 있으면 한국수출입은행 매매기준율. 휴일·고시 전에는 최근 영업일까지 최대 7일 거슬러 간다.
2. 없거나 실패하면 Frankfurter 공개 기준환율(키 불필요, 일 단위, 상업 이용 가능). 1시간 캐시, 실패 후 5분 뒤 재시도.
3. 둘 다 실패하면 김프를 `null`로 보내고 화면에 "환율 미확보"를 표시한다. 고정 환율로 대체하지 않는다.

USDT 기준 차이(`premium_usdt`)와 테더 프리미엄(`tether_premium`)은 따로 보낸다. `(1+premium_usdt)(1+tether_premium) = 1+premium` 관계다.

**시세** (`backend/market.py`): 대상은 업비트 KRW ∩ 바이낸스 USDT 현물 중 거래 상태가 `TRADING`인 코인이다. 거래가 멈춘 심볼도 현재가 응답에 마지막 가격이 남아 있어, 걸러내지 않으면 김프가 수천 %로 나온다(실측: DATA +16,826%, PROS +1,540%, WAVES −75.8%). 거래 상태 조회가 실패하면 대표 10개로 좁힌다. 화면에는 지금처럼 대표 10개만 보내고, 전체는 RAG 근거에서 쓴다. 갱신에 실패하면 이전 값과 함께 `error`에 원인을 담는다.

**거래소 상태** (`backend/exchange_status.py`): 빗썸 입출금 현황·빗썸 경보제·업비트 유의/주의를 수집한다. 바뀐 순간만 `exchange_*_changes`에 남기고 현재값은 `exchange_*_latest`에 둔다. 경보는 현재 활성 전체로 받으므로, 호출이 실패하거나 응답 형식이 틀리면 예외로 올려 진행 중인 경보를 종료시키지 않는다. 테이블은 `exchange_` 접두어로 기존 공지 테이블과 분리했다.

**실시간 근거** (`backend/live.py`, `backend/pipeline.py`): 질문마다 시세·김프 스냅샷과 입출금·경보 상태를 기준 시각이 붙은 근거로 만들어 메타데이터 다음에 넣는다. 색인하지 않는다(검색되는 순간 지난 값이 된다).
- 현재 값을 묻는 질문은 필요한 종류(시세 / 상태)의 **최신** 실시간 근거가 있을 때만 모델을 부른다. 시세는 1분, 상태는 45분(15분 크론 3회)을 넘기면 최신이 아니다.
- 생성된 답이 실시간 근거를 인용하지 않으면 규칙 판정으로 쓰지 않는다(`live_citation_missing`).
- 예측·매매 판단 질문은 근거가 있어도 계속 거절한다.
- "왜 김프가 높아?"처럼 현재 값을 묻지 않는 질문에도 실시간 근거가 함께 들어가, 입출금 중지·경보·공지를 연결해 설명할 수 있다.

**상시 수집** (`scripts/cron_collect.py`): Render 크론이 15분마다 빗썸 공지 동기화와 거래소 상태 수집을 한 번 실행한다. 무료 웹 서비스가 잠든 동안의 공백을 메운다. 의존성은 `requirements-cron.txt`만 쓴다(Chroma·LangChain·torch를 불러오지 않음을 import 추적으로 확인). 15분 간격은 Neon 무료 한도(월 100 컴퓨트 시간)를 고려했다. 1분 간격이면 DB가 잠들지 못해 약 17일 만에 한도를 다 쓰고, 같은 DB를 쓰는 웹 서비스도 멈춘다. 빗썸 공지는 최근 20건을 주므로 15분 간격으로도 빠지지 않는다.

## 검증

- 테스트 53개 통과(기존 26 + 신규 27). 신규 테스트는 실측 응답 모양을 쓴다: 거래 중단 심볼, 쉼표가 들어간 환율, 휴일의 빈 배열, 문자열 0/1, 200 응답의 오류 객체.
- 핵심 방어 4곳을 일부러 망가뜨려 해당 테스트가 실패하는지 확인했다: BREAK 필터, 실시간 근거 인용 판정, 형식 오류 응답 처리, 공식 환율 기준 김프. 처음에는 형식 오류 응답 경우가 빠져 있어 망가뜨려도 통과했고, 그 경우를 추가했다.
- 운영 환경 확인은 배포 후 별도로 기록한다.

## 남은 문제

- 화면 표는 여전히 대표 10개만 보여 준다. 전체 코인 표시는 프론트 표 구조를 바꿔야 한다.
- 빗썸 입출금 현황은 구버전 공개 API이고 0/1 의미는 실측 추론이다(BTC·ETH가 1). 업비트 입출금 현황은 키가 필요해 수집하지 않는다.
- 기준 환율은 고시 시점 값이라 고시 이후 환율 변동분이 김프에 섞인다. 근거와 화면에 고시일을 표시한다.
- 실시간 질문 분류는 여전히 정규식이다. 우회 표현을 모두 잡지는 못한다. 대신 생성 후 인용 판정이 두 번째 방어선이다.
